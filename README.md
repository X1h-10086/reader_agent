## 二、系统一句话概览

```
上传文档 → MinerU 解析(带坐标) → 章节树切片 → ┬─ 硬规则(确定性,零成本) ─┐
                                              └─ 检索证据 → LLM 语义判定 ─┴→ 证据校验 → 分级裁决
                                                                                    ↓
                                                        低置信度 → 人工介入 → 报告 → 回流评测
```

**五条设计原则**：确定性优先 · 证据先行 · 分层解耦 · 一切可回放 · 人在环上。

**技术栈**：FastAPI(:8000) + LangGraph + MinerU + DeepSeek API + SQLite→PostgreSQL/pgvector + Vite/Vue3(:5173)。

## 二之一、🚨 学习方式：一次只推进一个功能

本项目**采用单功能门禁制**，规则见 [docs/06-单功能学习门禁规范](./docs/06-单功能学习门禁规范.md)，当前状态见 [PROGRESS.md](./PROGRESS.md)（每次会话先读它）。

- 一次只有一个功能处于「学习中」或「待验收」；
- 通过 **A 概念关 / B 动手关 / C 观测关** 三关，由我宣告「F-xx 通过」后才打开下一个；
- 卡住时状态改「阻塞」并写明原因，不静默跳过；前置不足时会被冻结回退。

## 三、怎么使用这套文档（建议工作流）

1. **动手前**：读对应模块文档的「输入/输出契约」与「单元验收（DoD）」；
2. **做完前**：到 [docs/05](./docs/05-前后端联调与可验证矩阵.md) 找到该能力 ID（`CAP-Mx-nn`），确保三件事同时成立——**后端实现 / 探针台可见 / 业务页面可见**；
3. **编码时**：只依赖 `docs/03` 定义的数据结构，不跨模块引用内部实现；
3. **完成后**：逐条勾选 DoD，跑一遍阶段性的评测，确认没有退化；
4. **疑惑时**：回到对应模块文档的「常见坑」，多半已列出。

## 五、给完全新手的三句提醒

1. **别急着接大模型。** 阶段 3（纯规则）做扎实了，后面每一步都会轻松一倍。
2. **一切以证据为准。** 系统里任何一条结论，都必须能在原文点出位置——哪怕因此少报几条。
3. **每次改动都要能被评测看见。** 没有评测集，你永远不知道自己是在进步还是在绕圈。
