# 03 · 数据模型与接口契约

> 本文是**层与层之间的法律**：实体定义（数据库/ORM）与对外 API。任何模块若要跨层通信，必须引用这里的结构。
> 原则：**结构先行，代码后写**。先把这张表定死，后面 11 个模块可以并行开发。

---

## 📖 白话术语速查（读不下去时先看这张表）

| 术语 | 一句话白话 | 生活类比 | 常见误解 |
| --- | --- | --- | --- |
| **Block** | 文档被切成的一块块内容，每块带"第几页、什么位置、什么类型" | 拆包后贴了标签的小件 | ❌ 以为是"标签" → 其实是**贴了标签的内容** |
| **Chunk** | 几块 Block 拼成的一段完整语义，带章节标题前缀 | 装了箱的货，箱外写"第五章" | ❌ 以为和 Block 一样 → Block 是砖，Chunk 是墙板 |
| **Evidence 证据** | 从原文（或法规库）摘出来的**原话** + 它的位置 | 律师用荧光笔划的那句 | ❌ 以为可以改写 → **逐字摘录，改一个字就是伪造** |
| **Finding 意见** | 一条结论：什么问题、多严重、多大把握 | 意见书上的一条 | ❌ 以为只是 LLM 说的 → 规则和人工产出的**也是** |
| **bbox** | 内容在页面上的矩形坐标（归一化 0~1） | 照片上的方框选区 | ❌ 存像素 → 缩放就错位 |
| **char_span** | 在全文里第几个字符到第几个字符 | 书上的"第 100 页第 3 行" | 用于毫秒级校验"这话是不是真来自原文" |
| **severity** | 阻断 / 严重 / 一般 / 建议 | 急诊 / 住院 / 门诊 / 养生建议 | ❌ 等级 ≠ 置信度 |
| **confidence** | 这条结论多大把握（0~1） | 降水概率 80% | 硬规则恒为 1.0 |
| **locator** | 前端用来画高亮的位置信息包 | 导航坐标 | 由程序反查，禁止模型编造 |

**四个概念谁产出**：`Block`←M1 解析 ｜ `Chunk`←M2 切片 ｜ `Evidence`←M4 检索 + M5 校验 ｜ `Finding`←M3 规则 / M5 LLM / M7 人工。

> ⚠️ **学习侧重点**：字段细节**照抄即可，不用背**；类型标注语法（如 `list[float]`、`｜None`）**不考**，报错问我。
> 真正要理解的是「为什么需要它」，规则见 [06 §学习侧重点](./06-单功能学习门禁规范.md)。

## 2. 实体定义（Pydantic 模型 + 关系表说明）

### 2.1 Document / Version / Block

```python
class Document(BaseModel):
    id: str                      # uuid
    tenant_id: str
    title: str
    source_format: str           # pdf | docx | pptx | png | jpg
    doc_type: str                # contract | invoice | tender | generic
    status: str                  # uploaded | parsing | parsed | failed
    created_by: str
    created_at: datetime
    current_version: int = 1

class DocumentVersion(BaseModel):
    id: str
    document_id: str
    version: int
    file_hash: str               # sha256，用于去重
    storage_uri: str             # ./data/docs/{hash}.pdf
    page_count: int
    parse_engine: str            # mineru-pipeline | mineru-vlm
    quality_score: float         # 0~1，解析质量，见 M1
    parsed_at: datetime | None

class Block(BaseModel):          # M1 输出的最小单元（★ 全链路可信的基石）
    id: str
    version_id: str
    idx: int                     # 阅读顺序
    type: str                    # title | text | table | figure | formula | caption | header | footer
    text: str
    page: int
    bbox: list[float]            # [x0, y0, x1, y1]，归一化到 0~1，避免不同 DPI 偏差
    raw_bbox: list[float]        # 原始坐标，便于排查
    char_span: tuple[int, int] | None   # 在 full_text 中的字符区间
    level: int | None            # 标题层级 1~6
    confidence: float = 1.0      # OCR/表格识别置信度
    meta: dict = {}              # 表格 HTML、公式 LaTeX 等
```

> ⚠️ **坐标归一化是硬要求**：存 `[0,1]` 归一化值 + 原始值双份。否则前端不同缩放比下高亮必偏移。

### 2.2 Chunk（切片）

```python
class Chunk(BaseModel):
    id: str
    version_id: str
    block_ids: list[str]         # 来源 block，用于证据回链
    text: str
    section_path: str            # "3.2.1 违约责任"，用于上下文增强
    page: int
    bbox: list[float]            # 合并后的包围盒
    char_span: tuple[int, int]
    tokens: int
    index_in_doc: int
```

### 2.3 Rule / RuleSet（规则与知识）

```python
class Rule(BaseModel):
    id: str
    scope: str                   # global | document        ← 支撑 R-04 文档级自定义
    document_id: str | None
    code: str                    # 业务码，如 CON-001
    name: str
    description: str
    enabled: bool = True
    engine: str                  # regex | dict | missing | numeric | structural | consistency | llm
    severity: str                # blocking | major | minor | advice
    doc_types: list[str]         # 适用的文档类型
    params: dict = {}            # 引擎参数：pattern / keywords / formula / prompt_key
    retrieve_required: bool = False   # 是否需要先检索证据
    kb_sources: list[str] = []   # 依赖的知识库集合
    message_template: str        # 意见文案模板
    remediation: str             # 修改建议模板
    version: int = 1
    created_by: str
    hit_count: int = 0           # 命中统计，用于规则治理
```

### 2.4 Evidence（证据）

```python
class Evidence(BaseModel):
    id: str
    chunk_id: str | None
    quote: str                   # 原文摘录（必须从原文截取，禁止改写）
    page: int
    bbox: list[float]
    char_span: tuple[int, int]
    retrieval_score: float       # 0~1
    source: str                  # document | kb law | kb template | kb case
    verified: bool = False       # ★ 是否通过回原文校验（M5）
    verify_reason: str | None
```

### 2.5 Finding（审核意见）

```python
class Finding(BaseModel):
    id: str
    task_id: str
    rule_id: str
    title: str
    content: str                 # 意见正文（给人看）
    severity: str                # blocking | major | minor | advice
    engine: str                  # rule | llm | human
    confidence: float            # 0~1
    evidence_ids: list[str]
    locator: dict                # {page, bbox, chunk_id} 前端高亮直接消费
    status: str                  # auto | confirmed | dismissed | modified | pending_human
    rationale: str | None        # 判定理由（尤其 LLM 的推理摘要）
    llm_model: str | None
    prompt_version: str | None
    created_at: datetime
```

### 2.6 ReviewOpinion（人工意见，与机器意见同构）

```python
class ReviewOpinion(BaseModel):

    user_id: str

    created_at: datetime
```

### 2.7 AuditTask / TraceStep

```python
class AuditTask(BaseModel):
    id: str
    document_id: str
    version: int
    ruleset_id: str
    state: str                   # running | waiting_human | done | failed | canceled
    progress: float              # 0~1
    stats: dict                  # {findings_total, by_severity, tokens, cost, elapsed_ms}
    started_at: datetime
    finished_at: datetime | None

class TraceStep(BaseModel):      # 回放用
    id: str
    task_id: str
    node: str                    # parse | structure | retrieve | llm_audit | verify | ...
    seq: int
    input_digest: str            # 输入哈希 + 关键摘要（不存全量，避免爆库）
    output_digest: str
    elapsed_ms: int
    tokens_in: int = 0
    tokens_out: int = 0
    model: str | None
    prompt_version: str | None
    error: str | None
```

### 2.8 代码实现时的收口记录（F-01）

> 本节记录「文档 → 代码」过程中对上面字段做的调整。
> **规则：代码与文档不一致时必须回写到这里，不允许只改一边。**

| # | 位置 | 文档原文 | 代码做法 | 为什么 |
| --- | --- | --- | --- | --- |
| 1 | `Evidence.source` | `kb law` / `kb template` / `kb case`（带空格） | `kb_law` / `kb_template` / `kb_case` | 空格进 URL、进数据库、当枚举成员名，全是坑 |
| 2 | `Block.type`、`Finding.severity`、`Rule.engine`、`Rule.scope` 等 | 类型标注为 `str` | 用 `core/enums.py` 的枚举类接收 | 枚举是 `str` 的子类，不破坏契约；换来「拼错立刻报错」 |
| 3 | 所有 `bbox` | `list[float]` | 统一加 `min_length=4, max_length=4` | ★ 活例子：Pydantic **只拦你写明**的规矩。不写这句，传 3 个数字照放行 |
| 4 | `Finding.created_at` | 必填 | 给默认值 `datetime.now()` | 每次构造都手写时间没有意义 |
| 5 | `Rule.code` | `str`（业务码） | 加 `pattern=^[A-Z]{2,6}-\d{3}$` | 同上，写明才拦；想放宽就改这一处 |
| 6 | `Block.meta` | 未定义 | Adapter 写入保留键 `_adapter`（如 `confidence_provided`） | 记录「置信度是引擎给的还是我们默认填的」；质量评分据此判断该项是否有数据，避免拿假数据冒充满分 |

对应代码：`backend/core/enums.py`、`backend/core/models.py`；验收：`tests/test_models.py`。

## 4. REST API 契约

> 统一前缀 `/api/v1`，统一响应体 `{code, message, data, trace_id}`。错误码见下表。

### 4.1 文档与解析

| 方法 | 路径 | 说明 | 请求要点 | 响应要点 |
| --- | --- | --- | --- | --- |
| POST | `/documents/upload` | 上传文件（multipart） | file, doc_type | `{document_id, version, status}` |
| POST | `/documents/{id}/parse` | 触发解析 | `{mode: pipeline｜vlm}` | `{task_id, status}` |
| GET | `/documents/{id}/blocks` | 获取结构化结果 | `?page=&type=` | `{blocks:[Block], quality_score}` |
| GET | `/documents/{id}/file` | 原始文件流（前端 pdf.js 用） | — | PDF stream |
| GET | `/documents` | 文档列表分页 | `?page=&size=&status=` | `{items, total}` |
| DELETE | `/documents/{id}` | 删除文档及派生数据 | — | `{ok:true}` |

### 4.2 审核任务

| 方法 | 路径 | 说明 | 要点 |
| --- | --- | --- | --- |
| POST | `/tasks` | 发起审核 | `{document_id, version, ruleset_id, include_document_rules:true}` |
| GET | `/tasks/{id}` | 任务详情与进度 | `{state, progress, stats}` |
| GET | `/tasks/{id}/findings` | 意见列表 | `?severity=&status=&engine=` |
| GET | `/tasks/{id}/trace` | 回放链路 | `{steps:[TraceStep]}` |
| POST | `/tasks/{id}/resume` | 人工介入后继续执行 | `{human_ops:[...]}` |
| GET | `/tasks` | 任务列表 | 分页 + 筛选 |

### 4.3 规则管理（支撑 R-04）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/rules` | 列表（支持 `scope`, `document_id`, `doc_type` 过滤） |
| POST | `/rules` | 新建规则（可为文档级） |
| PUT | `/rules/{id}` | 修改并自动 `version + 1` |
| POST | `/rules/{id}/toggle` | 启停 |
| GET | `/rules/{id}/stats` | 命中率、平均耗时、误报反馈数 |
| POST | `/rules/preview` | **干跑试算**：不落库，直接在样例文本上看命中效果 |

### 4.4 人工复核

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/tasks/{id}/findings/{fid}/review` | `{action, comment, new_severity}` |
| POST | `/tasks/{id}/findings` | 人工新增问题（附 locator） |
| GET | `/tasks/{id}/export` | `?format=md｜docx｜pdf` 导出报告 |

### 4.5 WebSocket / SSE

| 通道 | 用途 | 消息示例 |
| --- | --- | --- |
| `WS /ws/tasks/{id}` | 实时进度与节点事件 | `{"node":"retrieve","progress":0.45,"msg":"检索完成"}` |
| `WS /ws/tasks/{id}/pending` | 等待人工的节点推送 | `{"type":"need_human","findings":[...]}` |

## 5. 错误码规范

| code | 含义 | 处理建议 |
| --- | --- | --- |
| 1001 | 文件类型不支持 | 前端提示支持列表 |
| 1002 | 文件超过大小上限 | 提示上限值 |
| 2001 | 解析失败 | 展示 trace_id，建议切换 VLM 模式重试 |
| 2002 | 解析质量过低 | 转人工校验入口 |
| 3001 | LLM 调用失败 | 自动重试 3 次（指数退避），仍失败则降级为仅规则结果 |
| 3002 | LLM 返回无法结构化 | 重试并追加格式纠正提示；二次失败则丢弃该规则结果并记 trace |
| 4001 | 预算超限 | 熔断，返回已完成部分 |
| 5001 | 权限不足 | 引导重新登录 |

## 6. 契约演进规则（避免后期返工）

1. **只增不改**：结构体字段允许新增（带默认值），不允许删除或改语义；不兼容变更走 `/api/v2`。
2. **枚举集中定义**：`severity / engine / status / block.type` 在 `common/enums.py` 单一来源，前后端共用（前端可由 OpenAPI 生成 TS 类型）。
3. **坐标统一**：一律 `[x0,y0,x1,y1]` 归一化浮点，左上角原点。
4. **所有实体带 `created_at` 与 `trace_id`**，保证可审计。
5. **契约测试**：每个 API 至少一个 contract test，防止"改字段忘了改前端"。
