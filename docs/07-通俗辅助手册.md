## 一、先记住这一个比喻：整个系统就是一家「快递验货中心」

把一份 PDF 想成一个**寄来的包裹**，我们的系统就是验货中心：

| 环节 | 验货中心在干什么 | 对应模块 | 产出 |
| --- | --- | --- | --- |
| 收件 | 收下包裹，登记"这是谁寄的、什么类型" | M1 接入 | `Document` |
| 拆包贴标 | 把里面的东西一件件拿出来，每件贴一张标签：**第几箱、放在哪个位置、是什么东西** | M1 解析 | `Block` |
| 装箱归位 | 零散小件按类别装进箱子，箱外写明「这是第五章的东西」，方便以后整体取用 | M2 切片 | `Chunk` |
| 建目录卡 | 给每个箱子做索引卡，以后问"付款条款在哪"能一秒翻到 | M2/M4 索引 | 索引 |
| **自动检查** | 拿检查清单逐条比对：数量对不对？有没有违禁品？少没少东西？ | M3 规则（分支 A） | `Finding` |
| **老师傅把关** | 清单查不了的（比如"这条款是不是明显不公平"），请有经验的老师傅看 | M5 LLM（分支 B） | `Finding` |
| 老师傅必须指位置 | 老师傅不能空口说，必须拿荧光笔划出"你看这一句" | M5 校验 | `Evidence` |
| 组长复核 | 重复的合并、没依据的扔掉、定严重等级 | M5/M6 裁决 | 定级 |
| 主管签字 | 拿不准的交给主管拍板：确认 / 驳回 / 改等级 | M7 人工 | 终态 |
| 出检验报告 | 整理成报告，每条都能点回原件位置 | M6 报告 | 报告 |
| **存档** | 今天验了什么、谁签的字，全部存档备查 | M8/M9 持久化 | 台账 |
| **复盘** | 每月统计"误报了多少、漏了多少"，回头改检查清单 | M10 评测 | 指标 |

**一句话串起来**：拆包贴标（Block）→ 装箱（Chunk）→ 查清单 + 问老师傅（两种 Finding）→ 老师傅必须指位置（Evidence）→ 复核定级 → 主管签字 → 出报告 → 存档复盘。

## 二、白话术语对照表（看正式文档卡住时来查）

| 术语 | 一句话白话 | 生活类比 | 常见误解 |
| --- | --- | --- | --- |
| **Block** | 文档被切成的一块块内容，每块带着"在第几页、什么位置、什么类型" | 拆包后贴了标签的小件 | ❌ 以为是"标签" → 其实是**贴了标签的内容** |
| **Chunk** | 几块 Block 拼成的一段完整语义，带章节标题前缀 | 装了箱的货，箱外写着"第五章" | ❌ 以为和 Block 一样 → Block 是砖，Chunk 是预制墙板 |
| **Evidence 证据** | 从原文（或法规库）里摘出来的**原话** + 它的位置 | 律师用荧光笔划的那句话 | ❌ 以为可以改写 → **必须逐字摘录，改一个字就算伪造** |
| **Finding 意见** | 一条审核结论：什么问题、多严重、有多大把握 | 意见书上的一条 | ❌ 以为只是 LLM 说的 → 规则和人工产出的**也是 Finding** |
| **bbox** | 一块内容在页面上的矩形坐标 | 照片上的方框选区 | ❌ 以为存像素 → 必须存**归一化 0~1** |
| **char_span** | 这段话在全文里是第几个字符到第几个字符 | 书上的"第 100 页第 3 行" | 用于毫秒级校验"这句话是不是真来自原文" |
| **切片 / Chunking** | 把长文档切成一段段便于检索和喂给模型 | 把长视频切成小段 | 切太碎 → 模型只见半句话 |
| **Embedding 向量** | 把一段话变成一串数字，意思相近的数字也相近 | 给每段话做一个"指纹" | 不是加密，是**语义的数字化** |
| **检索 / RAG** | 先从文档里找相关资料，再让模型看着资料回答 | 开卷考试（先翻书再答题） | ❌ 闭卷考 = 幻觉来源 |
| **Rerank 重排** | 对找出来的候选再排一次序，把最相关的放前面 | 初筛后复试 | 不加也行，加了准很多 |
| **置信度 confidence** | 这条结论有多大把握（0~1） | 天气预报"降水概率 80%" | 硬规则恒为 1.0（因为它不会"这次灵不灵"） |
| **severity 严重等级** | 阻断 / 严重 / 一般 / 建议 | 病情分级：急诊 / 住院 / 门诊 / 养生建议 | 等级≠置信度：把握很大也可能是"建议" |
| **编排 Orchestration** | 安排"谁先做、谁后做、谁和谁一起做、卡住了找谁" | 工程总包的施工计划表 | 不是"让 AI 自己决定干啥" |
| **LangGraph** | 一张流程图 + 一个共享记事本 + 能随时暂停存档 | 带存档点的关卡游戏 | 关键不是"能分叉"，是**能暂停、能恢复、能回放** |
| **interrupt 中断** | 流程跑到一半停下，等人给意见再继续 | 游戏暂停，等玩家选择 | 需要"存档（Checkpointer）"才能真暂停 |
| **Checkpointer** | 把流程当前状态存下来，重启也不丢 | 游戏存档点 | 用内存的 = 关电脑就没了 |
| **Trace** | 每一步干了什么、花了多久、花了多少钱的流水账 | 快递物流轨迹 | 没有它，出问题只能靠猜 |
| **持久化** | 存到数据库/磁盘里，关机也在 | 存档 | 不只是"存数据"，更是**复盘与学习闭环的地基** |
| **Pydantic** | 数据格式模板，填错就当场报错 | 快递面单：缺电话就不收 | 它就是"契约"的执法者 |
| **enums 枚举** | 某个字段只能是固定的几种值之一 | 红绿灯只有红黄绿 | 防止拼写成 `blcoking` 导致漏判 |
| **Mock** | 假数据，用来在后端没做好时先开发前端 | 排练时用的道具 | 必须打角标，否则会误以为已完成 |
| **API / 接口** | 前后端约定的"点菜单" | 菜单：你点什么，我给什么 | 契约变了两边都要改 |

## 三、四层代码结构：就是一家餐厅

```
api     服务员   ← 接待客人、传菜、不自己做菜
service 领班     ← 安排流程：先做哪个菜、要不要退菜
domain  厨师     ← 真正干活：切菜、炒菜
infra   仓库水电 ← 提供米面油和灶台
```

**为什么禁止"厨师去前台收银"（domain import fastapi）？**
因为一旦厨师认识菜单，你想换一家餐厅（换框架/换界面），厨师就跟着失业了。**厨师只认识食材，谁端盘子都不影响他做菜。**

## 四、F-01 通俗卡：为什么第一个功能是"定数据结构"

### 4.1 为什么先定结构再写代码？

盖房子前要先定**砖的尺寸**。如果砖有三种尺寸，砌到三楼才发现对不上，全拆。

数据结构就是"砖的尺寸"。`Block` 里有 `bbox`，后面 24 个功能全部依赖它——M2 切片要用、M5 校验证据要用、前端画高亮要用。**现在定错，后面每个功能都要返工。**

### 4.2 enums（枚举）是啥？

`severity` 只能是 `blocking / major / minor / advice` 四种之一。

如果不用枚举，各处写字符串，迟早有人写成 `"bloking"` 或 `"严重"`，程序不报错但**永远匹配不上**，那条意见就悄悄消失了——这是最难查的 bug。

```python
# backend/core/enums.py —— 全项目唯一真源
from enum import Enum

class Severity(str, Enum):
    BLOCKING = "blocking"   # 阻断：必须改
    MAJOR    = "major"      # 严重
    MINOR    = "minor"      # 一般
    ADVICE   = "advice"     # 建议
```

以后任何地方都写 `Severity.BLOCKING`，写错 IDE 立刻标红。

### 4.3 Pydantic 是啥？

就是**带校验的数据模板**，照着 `docs/03` §2 抄字段即可。它会在数据进来时自动检查：

```python
# backend/schemas/document.py —— 照 docs/03 抄字段
from pydantic import BaseModel, Field

class Block(BaseModel):
    id: str
    idx: int                                   # 阅读顺序
    type: str                                  # title/text/table/...
    text: str
    page: int
    bbox: list[float] = Field(min_length=4, max_length=4)  # 必须是4个数
    char_span: tuple[int, int] | None = None
```

好处：少字段、类型错、bbox 不是 4 个数 → **当场报错**，不会带着脏数据跑三个模块后才崩。

### 4.4 本功能要到什么程度？

**只要"能跑通上传"**，不要多写：
- 一个上传接口（只存文件，不解析）
- 前端一个按钮 + 一个列表
- 一个 pytest 证明"填错数据会被拦住"

```python
# backend/api/v1/documents.py
from fastapi import APIRouter, UploadFile, File
import shutil, uuid, pathlib

router = APIRouter()
DATA = pathlib.Path("data/docs"); DATA.mkdir(parents=True, exist_ok=True)

@router.post("/documents/upload")
def upload(file: UploadFile = File(...)):
    doc_id = str(uuid.uuid4())
    (DATA / f"{doc_id}_{file.filename}").write_bytes(file.file.read())
    return {"code": 0, "message": "ok", "data": {"document_id": doc_id}}
```

## 八、学习侧重点：什么必须懂、什么可以查、什么先别管 ★

> **总原则：80% 的时间花在"为什么"，20% 花在"怎么写"。** 语法细节是字典，用到再查；机制理解是地基，缺了就塌。

### 8.1 三层优先级

| 层级 | 内容 | 要求 | 例子 |
| --- | --- | --- | --- |
| **L1 机制层**（必须内化） | 为什么需要它？它解决什么问题？不这样做会怎样？ | **能用自己的话讲出来** | Block 为什么必须带 `bbox`；为什么先有 Evidence 再有 Finding；为什么要枚举 |
| **L2 契约层**（会查会用） | 有哪些字段、取值范围、谁产出 | **照 `docs/03` 抄对即可**，不用背 | `severity` 四种；`Block` 有 `page/bbox/char_span`；`engine` 三种 |
| **L3 语法层**（先别管） | Python 类型标注写法、泛型、`｜None`、`tuple[int,int]`、Pydantic 高级用法 | **不考，报错再说** | `list[float]`、`Field(min_length=4)`、`Literal[...]` |

### 8.2 对应到三道关卡（不用担心考语法）

| 关卡 | 考什么 | 不考什么 |
| --- | --- | --- |
| A 概念关 | **只考 L1**：机制与为什么 | 字段名、类型写法 |
| B 动手关 | 跑得起来 + 字段抄对（**L2**） | 代码风格、类型优雅度 |
| C 观测关 | 页面上能看见效果 | 实现方式 |

> **结论：三关都不考 L3。** 类型标注写错了？把报错贴给我，我改；不要为它卡住超过 15 分钟。

### 8.3 遇到类型/语法报错怎么办

1. **照抄优先**：字段一律从 `docs/03` 抄，别自己发明命名；
2. **报错就贴给我**：我直接给改好的那一行，顺带用一句话说清为什么；
3. **不追根究底**：本阶段目标是"跑起来并理解"，不是成为 Python 类型专家。

### 8.4 每个功能的「三句话」达标线（讲得出这三句 = L1 达标）

| 功能 | 三句话 |
| --- | --- |
| **F-01** | ① 为什么要先定数据结构（砖的尺寸）② 枚举防的是什么问题（拼错导致漏判）③ Pydantic 帮我们拦什么（脏数据） |
| F-02 | ① 为什么能力要由后端注册驱动 ② "不可观测 = 未实现"靠什么落实 ③ 探针台和正式页面分别看什么 |
| F-03 | ① 为什么先去重 ② 为什么不能只信 Content-Type ③ 为什么要转成统一格式 |
| F-04 | ① 为什么要写 Adapter ② 坐标为什么要存两份 ③ `char_span` 用在哪 |
| F-05 | ① 为什么标题要拼进 chunk 前缀 ② 为什么禁止跨章节合并 |
| F-06 | ① BM25 与向量各补什么短板 ② RRF 好在哪 |
| F-07 | ① 高亮偏移的三个原因 ② 为什么允许 Markdown 降级 |
| … | 后续功能通过时逐条追加 |

> **用法**：每学完一个功能，只检查自己能不能讲出这三句话。讲得出就提交验收，讲不出就先别赶。
