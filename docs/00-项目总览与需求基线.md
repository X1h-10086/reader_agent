## 1. 项目是什么

**智能文档审核 Agent**：一个本地可部署的 Web 系统，用户上传专业文档后，由「文档解析 + 规则/知识 + Agent 编排」三大技术模块协同，自动完成合规性检查，输出**带原文位置高亮**的审核意见，并允许人工随时介入。

一句话概括价值主张：

> **不让 LLM 直接"判合同"，而是让 Agent 先把文档变成可信的结构化证据，再让 LLM 基于证据下结论，最后把结论交给人拍板。**

## 2. 四大核心功能（源自项目文档 §核心功能）

| 编号 | 功能 | 原文要点 | 拆解后的子需求 |
| --- | --- | --- | --- |
| **R-01** | **多格式文档上传与解析** | 支持 `.pdf`，可扩展 `.doc/.docx/.ppt/.pptx/.png/.jpg/.jpeg` | ① 统一上传入口与格式嗅探；② PDF 走 MinerU；③ Office/图片走转换或 OCR 兜底；④ 格式扩展点插件化 |
| **R-02** | **结构化提取 + 位置信息 + 高亮展示** | 高精准度提取文本内容与**位置信息**并高亮 | ① 解析结果需保留 bbox/页码；② 文本块与坐标建立映射；③ 前端按坐标渲染高亮层 |
| **R-03** | **人机交互，人工随时介入审核** | 人工可介入流程并给出审核意见 | ① LangGraph `interrupt` 断点；② 人工意见与机器意见同等结构存储；③ 支持"重审/补充/驳回" |
| **R-04** | **单文件在线自定义规则 + 实时重审 + 持久化** | 针对单个文件自定义规则并重发审查 | ① 规则作用域：全局 / 文档级；② 规则变更触发增量重审；③ 审核结果版本化落库 |

> ⚠️ R-02 与 R-04 是本项目的差异化难点：**位置高亮**决定了证据可信；**在线自定义规则**决定了能否真正落地到业务。

## 3. 为什么要做成 Agent（而不是一次提问）

源自项目文档 §Agent 能力四点 + 三大核心技术模块：

| LLM 原生缺陷 | Agent 化对策 | 对应模块 |
| --- | --- | --- |
| 长文档装不进上下文 / 塞进去也记不住 | 解析 → 结构化 → 切片 → 检索，按需取证据 | M1、M2、M4 |
| 不知道企业私有规则与法规 | 规则引擎（可配置/可版本化）+ 法规知识库 RAG | M3、M4 |
| 结论无出处，无法向业务交代 | 每份证据必须携带 bbox / 页码，回链原文 | M2、M5 |
| 一次推理想不清楚复杂条款关系 | 计划 → 工具调用 → 反思的多步编排 | M6 |
| 低置信度结论直接外泄造成事故 | 低置信度自动路由到人工闸门 | M6、M7 |
| 上线后无法衡量效果好坏、无法回滚劣化 | 字段级 + RAG 两路评测 + Tracing | M10 |

**Agent 的四大能力在本项目的具体落点：**

1. **自主推理** → 语义类规则判定（条款是否失衡、是否存在歧义）
2. **工具编排** → 调用规则引擎、检索器、计算器（金额/日期核算）、数据库
3. **知识检索** → 法规/制度/历史判例检索后**引用作答**
4. **链式思考** → 多步：抽取要素 → 逐条比对 → 汇总定级 → 生成报告

## 4. 应用场景与难度（源自项目文档）

| 场景 | 审核内容 | 难度 | 对本系统的特殊要求 |
| --- | --- | --- | --- |
| 法务合同审核 | 必要条款检查、法律风险识别、措辞合规 | ⭐⭐⭐⭐⭐ | 语义判定比重高 → 更依赖 RAG + 人工兜底 |
| 财务票据校验 | 真伪、金额计算、政策合规 | ⭐⭐⭐⭐ | 键值对抽取、数值计算 → 需 **Calculator 工具**保证算术不靠 LLM |
| 标书/公文审核 | 格式规范、必备内容、章节完整性 | ⭐⭐⭐ | 结构与缺失检测 → 硬规则引擎为主 |

> **设计含义**：三类场景的"确定性/语义"配比不同，因此规则类型必须可混合编排（见 M3 + M6）。

## 5. 落地收益基线（源自论文 arXiv:2401.16212）

| 维度 | 论文结论 | 本系统的对应度量指标 |
| --- | --- | --- |
| 准确性 | 先进大模型可达甚至超过人类 | 评测集上的 precision / recall（M10） |
| 速度 | 秒级 vs 人类数小时 | 端到端 P95 延迟（M11） |
| 成本 | 降至 1/万 量级 | 单文档 token 成本 + 缓存命中率 |

> 这三个数字就是**项目上线后必须能量化出来的三项账**。别只做功能，要把基线先埋进去（见 M10 埋点设计）。

## 6. 非功能需求

| 编号 | 需求 | 建议目标（待你确认后固化） |
| --- | --- | --- |
| NFR-01 | 本地可一键部署 | `./install.sh && ./start.sh` 后浏览器可访问，无需手工干预 |
| NFR-02 | 可溯源性 | 100% 审核意见携带有效 bbox/页码；抽检定位命中率 ≥ 95% |

| NFR-07 | 资源可控 | 支持 CPU 轻量模式（Pipeline 解析 + 云端 LLM）与 GPU 全量模式（VLM 解析 + 本地模型）双档 |

## 7. 范围边界

**本期做**（对齐课程四大功能 + 部署章节）：

- 单文件上传解析与责任人/tenant 隔离（最小版）
- 规则在线自定义（文档级）+ 实时重审
- 位置级高亮与双栏审阅
- 人机介入与意见落库
- 本地一键部署（前后端 + 依赖 + 环境变量）

**本期不做**：多文档交叉审阅对比、自动改写（rewriting）、团队协作与审批流引擎、企业级 SSO / 细粒度 RBAC。
（明确划清，避免"做着做着变成另一个项目"）

## 10. 项目级完成标准（DoD）

- [ ] 上传一份 PDF，**无需人工干预**产出分级审核意见，且每条意见都能在原文高亮定位；
- [ ] 在页面上新增一条自定义规则 → 点击"重新审查" → 结果中出现该规则命中的条目，且已持久化；
- [ ] 审核进行到低置信度节点时流程挂起，人工给出意见后继续执行到出报告；
- [ ] `install.sh` + `start.sh` 在干净机器上一条龙跑通（前端 5173 / 后端 8000）；
- [ ] 具备 ≥ 30 份文档、≥ 150 条人工标注的回归评测集，可一键跑出 precision/recall。
