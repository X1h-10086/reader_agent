# M9 · 前端审阅台（Web Console）

> **职责**：把系统能力变成"审核员愿意每天用"的界面。
> **对应需求**：R-02（高亮展示）、R-03（人机交互）、R-04（在线规则 + 重新审查）
> **技术**：Vite + Vue3 + TypeScript，PDF 渲染用 pdf.js

---

## 1. 页面结构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部：应用名 │ 文档列表 │ 规则库 │ 任务中心 │ 评测 │ 设置     │
├───────────────┬──────────────────────────┬───────────────────┤
│ 左：           │ 中：PDF 原文            │ 右：意见面板       │
│ 文档树/进度    │  [高亮层覆盖]            │ 按等级分组         │
│ 规则清单       │                          │ 每条：标题/等级/   │
│                │                          │ 证据/确认驳回      │
└───────────────┴──────────────────────────┴───────────────────┘
```

**核心交互：点击右侧任一证据 → 中间 PDF 自动滚动并高亮到该段落。** 这一个交互做不好，整个产品的信任感就崩了。

---

## 2. 五个必备页面

| 页面 | 要点 |
| --- | --- |
| **上传页** | 拖拽上传、格式提示、解析进度条、质量分提示（低质量给出"切换深度解析"按钮） |
| **审阅工作台** | 三栏布局、Severity 色标、键盘快捷键（`Y` 确认 / `N` 驳回 / `J K` 上下条）、批量操作 |
| **规则管理页** | 列表 + 作用域筛选（全局/本文档）、表单式新建、**干跑预览**、启停、命中统计 |
| **任务中心** | 任务列表、状态筛选、重跑、查看 trace 回放、导出报告 |
| **文档详情** | 版本历史、历史审核记录对比（两次结果的 diff 视图） |

## 3. 高亮层的实现要点（本模块最难的部分）

```
pdf.js 渲染某页到 canvas
      ↓
按 bbox_norm × page_widthpx × scale 计算像素坐标
      ↓
在同一个容器的绝对定位 overlay div 上画半透明色块
      ↓
证据被 hover/click 时改色 + 滚动到视口
```

注意三点：
1. **页面 `rotation`**：扫描件可能被旋转，必须取 pdf.js 的 viewport rotation 做换算；
2. **缩放重绘**：`scale` 变化后必须重算所有矩形，不能缓存旧像素；
3. **bbox 是块级**而非句级：若要精确高亮到句子，需结合 `char_span` 在 pdf.js 的 text layer 中做字符级匹配（进阶功能，建议二期做）。

**降级方案**：若初次时间紧张，可用 Markdown 视图代替 PDF 渲染——把 `blocks` 按阅读顺序渲染为文本列表，同样按 `chunk_id` 高亮。**先把链路跑通，再追求视觉**。

## 4. 状态管理与数据流

- 全局：Pinia（`task`, `document`, `rule`, `user`）；
- 实时：`WS /ws/tasks/{id}` 推送进度与 `need_human` 事件，落地到 store 后由各组件订阅；
- 类型：由后端 OpenAPI **自动生成 TS 类型**（`openapi-typescript`），避免手写不同步；
- 乐观更新：人工确认/驳回先改本地 UI，再等服务端返回，失败回滚。

---

## 5. 体验红线

| 红线 | 为什么 |
| --- | --- |
| 不允许出现"转圈超过 10 秒无反馈" | 用户以为卡死后就再也不用了 |
| 每条意见必须能一键跳到原文 | 否则等于让用户盲信 |
| 必须有驳回入口 | 否则误报无法清理 |
| 必须显示来源（规则名/模型/置信度） | 建立信任的唯一方式 |
| 报告必须能一键导出 | 审核员要把它贴进流程系统 |

---

## 6. 输入 / 输出契约

消费后端 REST + WebSocket payload（见 [03 §4](../03-数据模型与接口契约.md)）。前端不直接触碰 MinerU / LLM / 数据库。

## 7. 单元验收（DoD）

- [ ] 上传 → 看到解析出的全文 → 发起审核 → 看到按等级分组的意见
- [ ] 点击证据能高亮并滚动到对应位置（偏差肉眼不可见）
- [ ] 在页面上新增一条规则并"重新审查"，新命中项出现且带该规则标识
- [ ] 人工确认/驳回后，等待中的任务继续执行到出报告
- [ ] 报告可导出为 Markdown / Word

---

## 8. 常见坑

| 坑 | 表现 | 解法 |
| --- | --- | --- |
| 直接 `<iframe src="blob">` 渲染 | 无法按坐标叠高亮 | 用 pdf.js canvas + overlay |
| 坐标未归一化 | 不同缩放高亮偏移 | 后端统一存归一化值 |
| 忘了扫描件旋转 | 高亮整体错位 90° | 换算时乘 rotation |
| 长任务无进度 | 用户以为挂了 | WS 推送 + 节点名文案 |
| 前端手写类型与后端漂移 | 字段 undefined | 从 OpenAPI 生成类型 |
