## 2. 关键选型深挖

### 2.1 为什么是 MinerU（而不是自己拼 PyMuPDF）

MinerU 的价值在于它**已经替你做完了最容易出错的脏活**（源自项目文档 §MinerU 工作流程）：

| 环节 | MinerU 做什么 | 自己做的痛 |
| --- | --- | --- |
| 预处理 | 判断语言/页面大小/**是否扫描件**/是否加密 | 需要自己判定要不要走 OCR |
| 布局分析 | LayoutLMv3 / DocLayout-YOLO 区分文本/表格/图像/标题 | 自写规则在复杂版面必错 |
| 公式 | YOLO 检测 + UniMERNet → LaTeX | 几乎无法自研 |
| 表格 | StructEqTable → HTML/LaTeX/Markdown | 表格还原是公认难题 |
| OCR | PaddleOCR | 中文识别率差一大截 |
| 后处理 | 修复重叠、按**人类阅读顺序**重排 | 多栏文档不重排则语义全乱 |
| 输出 | Markdown + JSON（含坐标） | 自建契约成本高 |

**双模式选择建议：**

| 模式 | 适用场景 | 硬件 | 速度 | 精度 |
| --- | --- | --- | --- | --- |
| **Pipeline** | 大多数常规文档，CPU 可跑 | CPU 可用 | 快 | 良 |
| **VLM（transformers / sglang）** | 复杂版面、手写、极低质量扫描件 | 需 GPU | 慢 | 优 |

> **落地策略**：默认 Pipeline，质量评分低于阈值时**自动切换 VLM 重试**（见 M1 降级策略）。这样既省资源又保质量。

### 2.2 为什么是 LangGraph

文档中提到"计划-工具调用-记忆-长流程编排 + 人类在环兜底"，映射到 LangGraph 的四个原语：

| 需求 | LangGraph 原语 |
| --- | --- |
| 各环节共享上下文 | `StateGraph` + `TypedDict State` |
| 并行扇出（规则 vs 检索） | 同一起点的多条边 + Fan-out 节点 |
| 条件路由（低置信度） | `add_conditional_edges` |
| 人工介入后继续 | `interrupt()` + `Checkpointer`（SQLite/内存） |
| 单步重跑与断点续跑 | `checkpoint` + `update_state` |

> **注意**：LangGraph 不是银弹。若你的流程其实是固定 5 步且无分支，用普通 Python 函数链更简单。**本项目因为需要"人在环"，所以值得上 LangGraph。**

### 2.3 为什么数值计算必须走工具（Tool）而不是 LLM

论文与工程实践一致：**LLM 的算术在多位数、多币种、含税计算上不可靠**。
因此 `Calculator` 工具负责：金额合计、大小写一致校验、日期先后、比例换算。LLM 只负责"用哪个数去算"和"解释结果"，不负责"算出结果"。

## 3. 环境准备（Windows / Linux 通用）

> 本机为 Windows；以下给出 PowerShell 与 Linux 两套写法。建议开发用 Python 虚拟环境，生产用 Docker。

### 3.1 依赖清单

```bash
# 运行时
python >= 3.10        # LangGraph 与新版 SDK 要求
nodejs >= 18          # Vite 前端
libreoffice           # Office → PDF 转换（headless）
libgl1 / poppler      # Linux 下 PyMuPDF / OCR 依赖
```

### 3.2 后端初始化（Windows PowerShell）

```powershell
cd d:\desktop\文档审核智能体\ai-document-review
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

```powershell
# .env 模板（勿提交仓库）
# LLM
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
LLM_TEMPERATURE=0

# 文档解析
MINERU_API_KEY=xxxxxxxx
MINERU_API_BASE=https://mineru.net/api/v4
MINERU_MODE=pipeline          # pipeline | vlm
MINERU_LOCAL=false

# 存储
DATA_DIR=./data
DATABASE_URL=sqlite:///./data/app.db
VECTOR_STORE=chroma           # chroma | pgvector

# 运行
BACKEND_PORT=8000
FRONTEND_PORT=5173
LOG_LEVEL=INFO
BUDGET_TOKEN_PER_TASK=200000
```

### 3.3 前端初始化

```powershell
cd frontend
npm install
npm run dev        # http://localhost:5173
```

### 3.4 一键启停脚本（对齐课程 `install.sh / start.sh / stop.sh`）

```powershell
# install.ps1  → 创建 venv、安装前后端依赖、初始化 data 目录
# start.ps1    → 先后台启动 uvicorn(:8000) 与 vite(:5173)，写入 logs/
# stop.ps1     → 按 PID 文件停止两个进程
```

Linux 版同理写成 `install.sh / start.sh / stop.sh`，用 `nohup ... & echo $! > .backend.pid` 记录 PID。

## 4. 版本兼容与踩坑预防

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| Python < 3.10 | LangGraph / Pydantic V2 安装失败 | 起始即锁定 ≥3.10，并在 README 标注 |
| Pydantic V1/V2 混装 | `ValidationError` 莫名其妙 | 全项目只用 V2，禁止引入依赖 V1 的旧包 |
| LangChain 版本漂移 | `with_structured_output` 行为变化 | `requirements.txt` 锁定小版本 |
| MinerU 返回字段变化 | bbox 结构不一致导致高亮偏移 | 在 M1 里做**适配层**：内部统一 `Block` 结构，外部差异一律隔离在此 |
| LibreOffice 未安装 | `.docx` 上传报转换失败 | `install.sh` 检测并提示安装命令 |
| Windows 中文路径 | pdf.js / OCR 输出乱码 | 中间产物统一放英文路径 `data/tmp`，用短路径名 |
| GPU 显存不足（VLM） | OOM | 默认关闭 VLM，仅在显式开关下启用 |
