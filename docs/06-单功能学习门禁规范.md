# 06 · 单功能学习与实现门禁规范

> **规则一句话**：一次只推进**一个功能**；这个功能必须「学完 + 实现完 + 在前端看得见 + 我确认通过」，才允许打开下一个功能。
>
> 本文定义：**状态机、通过标准、冻结与回退、会话衔接**。功能清单与逐条口述题在 [PROGRESS.md](../PROGRESS.md)。

---

## 1. 为什么需要门禁

自学项目的失败几乎都来自同一个动作：**还没消化就往下赶**。结果是后面积了一堆"好像懂了"的东西，一动手全卡住，然后推倒重来。

门禁只做一件事：把「我以为我懂了」变成「有证据地通过了」。

---

## 2. 状态机（每个功能只能处于其中一个状态）

```
未开始 ──► 学习中 ──► 待验收 ──► 已通过  ✅（唯一允许推进的出口）
   │          │          │
   │          └──► 阻塞 ─┘   ← 卡住必须写明原因，不允许静默跳过
   └──► 冻结                ← 前置薄弱被诊断出来时回退
```

| 状态 | 含义 | 可以做的事 |
| --- | --- | --- |
| **未开始** | 排队中 | 只读前置功能的相关章节，不做任何新东西 |
| **学习中** | 正在给答案/正在写代码 | 提问、写最小实验；**不得引入与当前功能无关的新技术** |
| **待验收** | 已提交产出，等待我判定 | 只做修正，不加新功能 |
| **已通过** | 我宣布通过 | 更新看板 → 打开下一个功能 |
| **阻塞** | 卡住超过预期 | 必须写明：卡在哪 / 已尝试什么 / 需要我提供什么 |
| **冻结** | 前置不足被暂停 | 先回退补课，补完再解锁 |

> **硬约束：任意时刻只有一个功能处于「学习中」或「待验收」。** 出现第二个 = 流程违规。

## 3. 三道关卡（缺一不可）

### 📖 先看这里：学习侧重点（什么必须懂、什么可以查、什么先别管）

> **80% 的时间花在"为什么"，20% 花在"怎么写"。**

| 层级 | 内容 | 要求 | 例子 |
| --- | --- | --- | --- |
| **L1 机制层**（必须内化） | 为什么需要它、不这样做会怎样 | **能用自己的话讲出来** ✅ 要考 | Block 为什么必须带 bbox；为什么先 Evidence 后 Finding |
| **L2 契约层**（会查会用） | 有哪些字段、取值范围 | 照 `docs/03` 抄对即可，不用背 | severity 四种；engine 三种 |
| **L3 语法层**（先别管） | 类型标注、泛型、Pydantic 高级用法 | **不考**，报错问我 | `list[float]`、`Field(...)`、`Literal[...]` |

**三关都不考 L3。** 语法卡住超过 15 分钟就把报错贴给我，我直接给改好的那一行。
每个功能只需能讲出它的「三句话」（见 `docs/07` §8.4），L1 即达标。

### 关卡 A · 概念关（是否真的懂）
- 我能用**自己的话**回答 PROGRESS.md 里该功能的**全部口述题**；
- 回答必须是**具体机制**（涉及具体字段、具体流程、为什么这样设计），**不能是套话**（如"用 RAG 提升准确性"不算通过）；
- **只考机制，不考语法与字段记忆**：类型标注、字段名细节可以从 `docs/03` 抄，卡住就问我（分层见 `docs/07` §8）。

### 关卡 B · 动手关（是否做出来了）
- PROGRESS.md 里列出的**产出文件全部存在且可运行**；
- 核心分支有测试或可复现的最小实验（跑一次给我看输出）。

### 关卡 C · 观测关（是否能在界面上被看见）
依据 `docs/05` 规则 V-02：
- `/console` 探针台有对应能力条目，能触发并看到原始响应；
- **至少一个真实业务页面**上能看到它的效果（不是只有 JSON）；
- 对应的 `CAP-Mx-nn` / `TC-xx` 判据通过。

## 4. 通过流程（严格按此执行）

```
⓪ 我先给出该功能的「通俗卡」（白话版：这玩意儿是啥、为什么需要它），
   收录在 docs/07-通俗辅助手册.md；用户说"懂了"再进正式卡
       ↓
① 我给出该功能的「学习卡片」：读什么 / 做什么 / 口述题
       ↓（用户学习并动手）
② 用户提交：产出文件路径 + 运行证据 + 口述题答案（或提出疑问）
       ↓
③ 我逐条核对三关卡：
       ├ 有任一关未达 → 状态变「待验收」，给出**具体缺什么**，不推进
       └ 三关达成   → 宣布「F-xx 通过」
       ↓
④ 更新 PROGRESS.md（日期 + 产出路径 + 备注）
       ↓
⑤ 打开下一个功能的学习卡片
```

**关键约束：第 ⑤ 步只能由我在第 ③ 步确认通过后执行。** 用户可以催，但不能自开新功能。

## 5. 冻结与回退（保护机制）

出现以下任一情况，我会主动把后续功能冻结并回退：

| 征兆 | 处置 |
| --- | --- |
| 口述题只能答出套话、讲不出机制 | 冻结当前功能，回退到相关前置功能重讲 |
| 产出能跑但说不清某个字段为什么存在 | 冻结，要求对该字段单独做个最小实验 |
| 连续两次同一功能的验收未过 | **强制回退**上一个已通过功能复习，不硬推 |
| 发现"后端没有、前端却是假的" | 冻结并补后端（违反 V-01） |

回退不是惩罚，是为了避免"地基空一层、上面盖三层"。

## 6. 会话衔接规则（跨对话不丢状态）

| 时机 | 必做动作 |
| --- | --- |
| 每次会话开始 | 先读 `PROGRESS.md`：确认当前功能与状态，再继续 |
| 每次会话结束 | 更新 `PROGRESS.md`：状态、产出路径、卡点、下一步 |
| 通过/阻塞发生时 | **立即**改看板，不等会话结束 |
| 新会话若跳过看板直接推进 | 视为违规，先补读再继续 |

---

## 7. 用户的三项权利

1. **随时提问**：学习中对任何概念都可以追问，我会用本项目语境解释，不泛泛而谈；
2. **要求放慢**：可以说"这里还不懂"，我会换一种讲法（画流程 / 做最小实验 / 举个反例），直到通过 A 关；
3. **拒绝推进**：觉得没吃透可以主动要求不验收，我不催进度。

---

## 8. 我的三项承诺

1. 一次只讲一个功能，不一次性倾倒全部内容；
2. 每个功能都给出「最小学会标准」，不用模糊表述敷衍；
2.5 每个功能**先给通俗卡（白话类比）再给正式卡**；用户说"看不懂"时立刻换讲法，不要求硬啃术语；
3. 未通过就说"未通过"，并明确指出**具体缺哪一项**，不含糊放行。
